# Отчёт по лабораторной работе №1

## Тема: цветовые модели XYZ, LAB, HSL и переходы между ними

**Вариант:** 11 — XYZ ↔ LAB ↔ HLS

---

## 1. Цель работы

Изучить принципы построения цветовых моделей XYZ, LAB и HSL, освоить математический аппарат перевода между ними, а также реализовать веб-приложение, позволяющее пользователю интерактивно задавать цвет и наблюдать его представление одновременно в трёх моделях.

## 2. Постановка задачи

Требовалось разработать приложение со следующими возможностями:

- задание цвета тремя способами: точный ввод в поля, выбор из палитры, плавное изменение ползунками;
- автоматический пересчёт всех представлений цвета при изменении любой координаты;
- выбор стандарта освещения (D65, D50, E) с пересчётом матриц перехода «на лету»;
- выбор стратегии при выходе значения за границы модели (Clipping или Scaling);
- интерактивные градиенты под ползунками, показывающие результат изменения координаты;
- вывод ненавязчивого предупреждения при обрезании или масштабировании;
- отсутствие жёстко зашитых констант перевода в XYZ и LAB;
- разделение кода на слои Model, View и Controller/ViewModel;
- автоматические микротесты для проверки математики.

## 3. Архитектура приложения

Приложение разделено на три независимых слоя.

**Model** (`Model`, IIFE-модуль в `script.js`) — содержит только математику. Модуль ничего не знает про DOM, не обращается к элементам интерфейса и не зависит от состояния приложения. Наружу экспортируются функции `getIlluminantData`, `rgbToXyz`, `xyzToRgb`, `xyzToLab`, `labToXyz`, `rgbToHsl`, `hslToRgb`, `hexToRgb`, `rgbToHex`.

**View** (`index.html`, `style.css`) — разметка и оформление. Каждый параметр модели описан блоком `.param` с атрибутами `data-model` и `data-component`, внутри которого находятся ползунок, числовое поле и холст для градиента. Такая структура позволяет контроллеру автоматически находить нужные элементы без ручной привязки.

**Controller** (`ColorApp`) — связующее звено. Собирает текущее состояние, вызывает функции `Model`, обновляет интерфейс. Никаких математических расчётов внутри контроллера нет.

## 4. Математическая часть

### 4.1. Матрица перехода RGB → XYZ

Матрица строится динамически для каждого стандарта освещения. Сначала формируется матрица цветностей на основе координат основных цветов sRGB:

```
R = (0.64, 0.33)
G = (0.30, 0.60)
B = (0.15, 0.06)
```

Из них собирается матрица `M` в виде

```
| xr/yr   xg/yg   xb/yb |
|   1       1       1   |
| zr/yr   zg/yg   zb/yb |
```

где `z = 1 − x − y`. Затем вычисляется обратная матрица `M⁻¹`, умножается на вектор белой точки выбранного источника, что даёт масштабирующие коэффициенты `Sr, Sg, Sb`. Итоговая матрица `rgb2xyz` получается умножением столбцов `M` на эти коэффициенты.

Матрица обратного перехода `xyz2rgb` получается как обратная к `rgb2xyz` через функцию `matInv3x3`, вычисляющую определитель и алгебраические дополнения.

Благодаря такому построению в коде нет зашитых числовых матриц. При смене источника освещения (D65, D50 или E) вся цепочка пересчитывается заново. Используются следующие белые точки:

- D65 — X = 95.047, Y = 100, Z = 108.883;
- D50 — X = 96.421, Y = 100, Z = 82.518;
- E — X = 100, Y = 100, Z = 100.

### 4.2. Гамма-коррекция

Перед умножением на матрицу значения RGB нормализуются к диапазону [0, 1] и проходят линеаризацию по стандарту sRGB:

- при `c ≤ 0.04045`: `c / 12.92`;
- иначе: `((c + 0.055) / 1.055)^2.4`.

Обратное преобразование (после умножения на `xyz2rgb`) выполняется по формуле

- при `c ≤ 0.0031308`: `12.92 · c`;
- иначе: `1.055 · c^(1/2.4) − 0.055`.

### 4.3. XYZ → LAB

Нормируем координаты на белую точку, затем применяем функцию `f`:

- при `t > (6/29)³`: `t^(1/3)`;
- иначе: `t / (3 · (6/29)²) + 4/29`.

Далее координаты LAB вычисляются как

```
L = 116 · fy − 16
a = 500 · (fx − fy)
b = 200 · (fy − fz)
```

Обратное преобразование `labToXyz` получает `fx, fy, fz` из L, a, b, применяет функцию `f⁻¹` и умножает на белую точку.

### 4.4. RGB ↔ HSL

Перевод в HSL выполняется по стандартному алгоритму через максимум, минимум и разность каналов. Обратное преобразование — через хрому `c`, промежуточную величину `x` и добавку `m`. Оттенок возвращается в градусах (0–360), насыщенность и светлота — в диапазоне [0, 1].

### 4.5. Стратегии при выходе за границы

Если после перевода из XYZ в RGB хотя бы один канал оказывается вне [0, 255], применяется одна из двух стратегий.

**Clipping** — каждое значение просто прижимается к ближайшей границе: отрицательное к 0, больше 255 — к 255.

**Scaling** — весь диапазон каналов сжимается пропорционально так, чтобы минимальное значение стало 0, максимальное — 255. Если разброс между каналами пренебрежимо мал, все каналы устанавливаются в 127.5 (серый), чтобы избежать деления на ноль.

В обоих случаях возвращается флаг `clipped`, по которому контроллер выводит предупреждение пользователю.

## 5. Интерфейс

В верхней части страницы расположены три элемента управления: выпадающий список стандарта освещения, выпадающий список стратегии обработки границ и стандартный пикер цвета. Далее следуют три карточки — XYZ, LAB и HSL. В каждой карточке по три параметра, для каждого из которых предусмотрены ползунок, числовое поле и холст с градиентом.

Под карточками находится блок предпросмотра цвета и строка состояния, в которой выводится предупреждение об обрезании или масштабировании. В самом низу — блок с результатами автоматических тестов.

### 5.1. Способы задания цвета

**Ползунки.** Событие `input` на ползунке обновляет числовое поле и вызывает `onParamChange`, который пересчитывает цвет.

**Числовые поля.** При вводе значение не применяется мгновенно — оно только сохраняется как черновик в множестве `pendingInputs`. Пока пользователь печатает, `updateUI` не перезаписывает поле, поэтому курсор не прыгает и лишние знаки после запятой не появляются. Применение происходит по Enter, по Escape (отмена) или при уходе фокуса. Такой подход позволяет спокойно набирать длинные значения.

**Пикер цвета.** При изменении значения нативный элемент `input[type=color]` возвращает HEX-строку, которая через `hexToRgb` превращается в RGB и подаётся в `setFromRgb`.

### 5.2. Интерактивные градиенты

Для каждого ползунка на холсте отрисовывается горизонтальная полоса из 200 пикселей. Для каждой точки `px` вычисляется промежуточное значение координаты, остальные две координаты берутся из текущего состояния, выполняется перевод в RGB, результат записывается в `ImageData` и выводится через `putImageData`. При любом изменении цвета градиенты перерисовываются, поэтому они всегда соответствуют текущему контексту.

### 5.3. Предупреждения

При срабатывании флага `clipped` в блоке предупреждений появляется сообщение о том, что произошло обрезание или масштабирование. Если значение было ограничено диапазоном ползунка, в предупреждение добавляется соответствующая строка с указанием границ.
